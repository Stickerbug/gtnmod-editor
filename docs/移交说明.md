# GTN Mod Studio 移交说明

面向"接手继续做"的人。设计细节与决策依据见
`Python联机版/docs/模组编辑器设计.md`，本文只讲**现状、怎么跑、哪些坑**。

## 一、这套东西由什么组成

### 游戏仓库（`Python联机版/`）

| 路径 | 作用 |
| --- | --- |
| `tools/extract_op_schema.py` | 生成编辑器与运行时的唯一契约 `op-schema.json` |
| `tools/extract_card_text_rules.py` | 生成关键词规则、术语表、卡牌索引、样例卡数据 |
| `tools/extract_renderer_vendor.py` | 复制游戏渲染器整套（`game.js` / `style.css` / 字体 / 图标）到编辑器 |
| `tools/extract_card_css.py` | 只抽卡面 CSS 子集；已被 vendor 方案取代，保留作漂移检测 |
| `tools/mod_atom_report.py` | 原子长尾地图（谁还在、谁死了、谁被间接引用） |
| `tools/op_priority_report.py` | 用真实使用频率排句型优先级 |
| `tools/editor_coverage_report.py` | 覆盖率基线，可当原子重构的验收指标 |
| `app.py` | 新增 `GET /api/mod-studio/schema`、`POST /api/mod-studio/validate` |

### 编辑器仓库（`模组编辑器/`）

| 路径 | 作用 |
| --- | --- |
| `src/gtn-text/` | 文本层：`terms.js`（术语+表达式）、`templates.js`（句型+模板库）、`steps.js`（步骤树→效果行）、`render.js`（关键词着色）、`index.js`（组装） |
| `src/effect-editor.js` | 效果行编辑器组件（不依赖 Blockly） |
| `src/generated/` | 全部生成物 + `vendor/`（**不要手改**） |
| `preview/card-host.html` | 卡面渲染宿主页：加载 vendor 的 `game.js`，用游戏的 `GTN_CARD_RENDERER` 画卡 |
| `prototype/` | 设计稿：三栏界面 + 预览 iframe + 效果行验证页 |
| `vite.config.js` | 已配 `/api/mod-studio` 同源代理到游戏服务 |

## 四、坑与注意事项

1. **绝对路径**：游戏的 `game.js`/`style.css` 用 `/fonts/`、`/static/assets/` 取资源，
   直接搬到编辑器会 404——`extract_renderer_vendor.py` 已改写为相对路径，
   宿主页用 `<base href=".../vendor/">`，**vendor 的 css/js 引用必须写绝对路径**（base 会改相对路径解析）。
2. **跨源**：编辑器与游戏服务不同源，浏览器会拦。已用 Vite 同源代理解决；
   不要为编辑器在游戏服务上开 `Access-Control-Allow-*`。
3. **校验接口**：必须先 `apply_mod_locales()` 再 `validate_mod_v2(..., allow_reserved_namespaces=True)`，
   否则 20 个官方包里有 7 个会被误判非法。
4. **首帧时序**：iframe 就绪前的 `postMessage` 会丢，宿主页要回发 `gtn-card-host-ready`。
5. **卡面文字自适应**不要自己实现：游戏有 `fitCardEffectText()`，vendor 里就是它。
6. `prototype/` 是设计稿，删掉不影响正式功能；`src/generated/` 全部由脚本生成。

## 七、在线校验已接入 Studio（2026-09-11）

`v2Studio.js` 的 `refreshCompiledState({validate:true})` 现在做**两段校验**：

1. 本地 `validate()`：结构、命名空间、必填字段、资源 id 格式；
2. `validateWithServer()`：POST `/api/mod-studio/validate`，用**线上同一份 op 白名单**
   校验，结果以 `[服务端]` 前缀合并进同一个面板。

容错：连不上→降级为一条警告；413（超过 256 KB）与 429（限流）都只记警告，
不让编辑器因为服务端问题而报"模组有错"。

## 八、编辑器部署与版本号（2026-09-11）

线上地址 `https://gtn.stickerbug.top/studio/`，nginx `alias /opt/gtn-studio/dist/`
（`/studio/` 带 `Cache-Control: no-cache`，避免 index.html 被浏览器长缓存）。

**版本号**：`package.json` 的 `version` 是唯一来源，构建时由 `vite.config.js` 注入到
三处 —— 界面左上角标题旁的版本胶囊（悬停看构建时间）、`index.html` 的
`<meta name="studio-version">` / `<meta name="studio-build">`、以及顶部副标题。
所以"打开页面看到的版本号"就是"服务器上跑的那一版"，不用再靠猜。

```bash
# 1) 改 package.json 的 version（例如 1.1.0 → 1.1.1），然后构建
cd 模组编辑器 && npm run build      # dist/ 是提交进 git 的，构建后必须一起提交

# 2) 提交并推送（origin 是 GitHub 且连不上，用 gitee）
git add -A && git commit -m "chore: bump 版本号到 1.1.1" && git push gitee main

# 3) 服务器拉取（/opt/gtn-studio 的 origin 就是 gitee，不要换成 GitHub）
cd /opt/gtn-studio && git pull --ff-only origin main

# 4) 验证线上确实是这一版
curl -s https://gtn.stickerbug.top/studio/index.html | grep -E 'studio-version|assets/main-'
```

**踩过的坑**：编辑器产物有几 MB，`git pull` 与浏览器刷新之间会有几秒窗口，
期间打开页面可能仍是上一版 —— 先看版本胶囊再判断"改动没生效"。

### 线上 nginx（2026-09-11 修正，改的是游戏服务器 `/etc/nginx/sites-available/gtn`）

1. `/static/`、`/fonts/`、`/favicon.ico` 三个 `alias` 原先还指向**已退役的蓝绿目录**
   `/opt/gtn-next-5002/`，而 5002 早已 stop + disable。后果：`static/` 与 `next` 两份
   文件里，**8750 个只在正式目录里存在的文件全部线上 404**，其中就包括运行时生成的
   `static/assets/mod-card-art/*.svg`（模组卡图缓存，gitignore 掉、只存在于正式目录）。
   已全部改指 `/opt/gtn-release/`，实测原本 404 的卡图现在 200。
   **教训**：蓝绿退役时，除了把 `proxy_pass` 切回 5000，还要检查所有 `alias`。
2. `location /studio/` 里加了 `open_file_cache off;`。nginx 在 `http` 层开了
   `open_file_cache`（`valid 120s`），`git pull` 是通过 rename 换 inode 的，
   旧 inode 的文件描述符会被缓存到过期为止 —— 表现就是"pull 成功了但页面还是旧版"。
   编辑器只有几个静态文件，关掉文件缓存没有性能顾虑。
   （`/static/` 保持开启，那边靠 7 天强缓存，不靠 nginx 文件缓存正确性。）

**必须注意的坑（已踩）**：游戏服务对 POST 做同源检查，代理转发时带的是编辑器自己的
`Origin`，会被 403 `cross-site request rejected` 拦下。解法是在 Vite 代理里改写
`Origin`/`Referer` 为目标服务自身（`vite.config.js` 已配），**不需要放宽服务端 allowlist**。
编辑器将来部署到正式域名时，同样要在它自己的代理/后端做这一步改写。

实测：Studio 里点「校验」→ 底部面板显示 `错误 0 / 警告 5`，5 条全部带 `[服务端]` 前缀
（缺 locales、四语言翻译不完整），说明服务端结果正确合并。

## 九、导入 gtnmod 的三个坑（2026-09-11，v1.1.1 修完）

1. **警告面板显示的是"导入瞬间"的旧结果**。`.gtnmod` 的导入顺序是
   `importJson()` → `mergeLocalesFromZip()` → `loadAssetsFromZip()`，而校验只在
   `importJson()` 里跑过一次，那时 `draft.locales` 还没挂上，于是底部一直留着
   `[服务端] 模组未提供 locales/zh.json`、`zh 卡牌翻译缺少或不完整: 52/52` 这类
   其实已经过期的警告。修法：locales / 图片都挂好之后**再跑一次
   `refreshCompiledState({ validate: true })`**。（`importJson` 内部的校验不能删，
   用户单独导入 mod.json 时还要靠它。）
2. **卡图不显示是 MIME 问题**。JSZip 的 `entry.async('blob')` 会把 `.svg` 猜成
   `text/plain`，转成 data URL 后就是 `data:text/plain;base64,…`，
   `<img>` 直接不画（`naturalWidth === 0`，DOM 里看得到元素、看不到图）。
   修法：一律 `new Blob([buffer], { type: imageMimeTypeForName(path) })`，
   预览再按扩展名重建 data URL。另外游戏渲染器取图读的是
   `card.image / card.image_url`（见 `game.js` 的 `normalizeBattleCard`），
   不是 v2 的 `assets.image`，所以预览要**两个字段都写**。
3. **刷新页面后卡图会消失**：包内图片只在内存里（blob URL 活不过刷新），
   而自动保存只写 `mod.json` 那份 JSON。修法：图片额外缓存到
   `localStorage['gtn_mod_studio_assets_v1']`（上限 2.5 MB，超了就在运行时错误里提示），
   启动时 `restoreAssetCache()` 还原成 blob URL。缓存不写进导出包。

## 十、"事件有『已编辑』标记、效果行却是空的"（2026-09-11，v1.1.2）

症状：每张卡的效果逻辑面板都是空的，但左侧时点按钮上带着"已编辑"。

原因：`hasEventContent()` 把 `draft.editor.workspaces[key]` 也算成"这个时点有内容"。
那是 Blockly 时代存进草稿的工作区 JSON（旧编辑器每打开一个时点就写一份）。
画布已经移除，`workspaceToSteps()` 是空实现，于是出现了
**"标记说已编辑、效果行没步骤"** 的自相矛盾状态。用一份
"有 workspaces、没有 steps"的 JSON 导入即可复现。

修法：

1. `hasEventContent()` 只认 `steps`，不再看旧工作区；
2. 效果行面板顶栏显示 `效果行编辑器 · N 步`，空的时候一眼能看出是 0 步；
3. 该时点只剩旧版数据时，空状态直接说明"只有旧版 Blockly 积木，无法自动还原"；
4. 顶栏加「重置本地草稿」（清 autosave + 图片缓存后重载），
   用来一键跳出旧草稿；`tryLoadAutosave()` 检测到旧工作区时也会在"运行时错误"里提示。

## 十一、预览字体与游戏不一致（2026-09-11，v1.1.2）

游戏页 `templates/index.html` 里字体不是纯 CSS 加载的：
它用 JS `new FontFace('Kreadon', '/fonts/Kreadon-Regular.subset.woff2?v=3')`，
加载完成后给 `<html>` 加 `.fonts-loaded-main`，`style.css` 靠这个类把
`--font-main` 换成 Kreadon。而 `.card-english-name` 用的正是 `var(--font-main)`，
所以少了这一步，预览里的卡面英文名会退回系统字体（与游戏不同）。

`preview/card-host.html` 现在与游戏对齐：

* preload 用 `?v=3` 的完整 URL（否则和 CSS 里的 URL 不是同一个资源）；
* 注册 `FontFace('Kreadon')` 并加 `.fonts-loaded-main`；
* 除 `style.css` 外再加载 `card_compat.css` / `card_compat.js`（容器查询兜底），
  `<html>` 也带上 `lang="zh-CN" data-ui-style="minimal"`。

自检口径：在预览 iframe 里 `document.fonts.check('16px Kreadon')` 为 true，
`.card-english-name` 的 computed `font-family` 以 `Kreadon` 开头。

## 十二、"显示 N 步但一行都看不见"（2026-09-11，v1.1.3 / v1.1.4）

Blockly 画布删了，但逻辑面板里那个空的挂载点 `<div id="studio-blockly-area">`
连 CSS 一起留着，`style.css` 里它是 `height:100%; min-height:420px`。
而 `.logic-workspace-stage` 是 `grid-template-rows: auto minmax(0,1fr); overflow:hidden`，
于是 420px 的空占位吃掉了整格高度，**效果行编辑器被挤到可视区外**
（窗口越矮越明显；高窗口下偶尔能露出来，所以之前不容易复现）。

修法：

1. 删掉空占位与 `#studio-blockly-area` 的 CSS，逻辑面板里只留
   `.logic-workspace-stage`，效果行编辑器直接 `appendChild` 进去；
2. `initWorkspace()`（Blockly 注入）与"隐藏高级画布"按钮一并删除；
3. `.logic-workspace-stage` 改成 `flex:1 1 auto; overflow:auto`，作为唯一滚动容器；
4. 矮窗口让位：`@media (max-height:780px)` / `(max-height:640px)` 收缩顶栏与底部面板
   （64/208 → 56/150 → 52/118），把高度让给中间编辑区；
5. 切换时点或切卡时 `container.scrollTop = 0`，避免停在上一张卡的滚动位置。

自检口径（1000×600 视口）：`.gee-row` 的 `getBoundingClientRect()` 完全落在
`.logic-workspace-stage` 之内，且 `stage.scrollHeight === stage.clientHeight`。

## 十三、官方 DLC / 扩展包的三条规则（2026-09-11，v1.1.5–v1.1.8）

官方 20 个包全量导入过一遍，踩到三类误报，都已经按服务端口径修好：

1. **`manifest.resource_namespace`**：DLC 包形如 `id=bio_dlc` +
   `resource_namespace=bio`，卡牌 ID 全是 `bio:*`（7 个 DLC 都这样）。
   服务端 `mod_validator_v2` 用 `resource_namespace or manifest.id` 判定命名空间，
   编辑器之前只看 `manifest.id`，于是报"必须使用当前模组命名空间 bio_dlc:"。
   现在 `validate()`、`namespaceOf()`、`compileDraft()` 都按同一口径走，
   manifest 编辑器也多了"资源命名空间（DLC/扩展包才填）"字段。
   ⚠️ 注意 `compileDraft()` 不能再把 `manifest.id` 写成命名空间（那会把 `bio_dlc` 抹成 `bio`）。
2. **声明式事件**：`void:magic_copper_rod` 的 `on_damage_absorb`、
   `void:eyeball` 的 `on_target_restrict` 是配置对象而不是 `steps` 数组。
   本地校验不再报"steps 必须是数组"，效果行面板改成提示
   "这个时点用的是声明式配置（…）可以在 JSON 页签里改"，覆盖率行显示"此时点是声明式配置"。
3. **两类"看不见的定义"不要报**：
   * 标签引用：`sewers:confusion` 定义在同命名空间的 Sewers Cards Addition，
     `arctic:ready` 定义在别的包——服务端也不校验，报出来只有噪音；
   * capability：编辑器列表漏了 `ui_components` / `compatibility` / `logic_dsl` /
     `localization`，会把官方包误判成"未知 capability"。现已与
     `mod_spec_v2.VALID_CAPABILITIES` 对齐。

另外两条经验：

* **原子能力改完要重跑契约**：`declare_forced_target` 这类新 op 必须
  `cd Python联机版 && python tools/extract_op_schema.py` 重新生成
  `模组编辑器/src/generated/op-schema.json`，否则编辑器会报"未完全识别的 op"。
  但**服务端校验用的是线上代码自己的白名单**：新原子能力在游戏代码提交并部署前，
  服务端仍会报"不在 DSL 白名单中"（本次 Sewers Cards Addition 就是这个情况）。
* **服务端校验有限流**：120 次 / 300 秒 / IP。连续导入几十个包会看到
  `[服务端] 请求过于频繁，请稍后再试`，这是限流提示，不是模组的问题。

## 十四、效果行的三处改动（2026-09-11，v1.2.0–v1.2.3）

1. **伤害类型槽**：运行时认 `damage_type: "physical" | "magic"`（magic 在卡面画成
   `[[icon:electric_damage]]`，官方包的 `direct_damage` 魔法伤害都这么写）。
   之前 `deal_damage` 的槽把图标 token 当值写回（`damage_type: "[[icon:D]]"`，
   会被运行时归一成 physical），而 `direct_damage` 干脆写死 `[[icon:D]]`。
   现在两个 op 都带 `damage_type` 槽，选项是 `{value:'physical'|'magic', label:'[[icon:D]]'|'[[icon:electric_damage]]'}`，
   写回的是运行时值；历史草稿里写成图标 token 的会自动归一。
2. **一行就是一行**：`.gee-row` 从 `flex-wrap: wrap` 改成 `nowrap` + 横向滚动，
   槽位宽度设上限（下拉 124px、数字 48px），行高从三行降到 ~40px；滚动条隐藏，
   免得每行再多 12px。窄窗口下仍可横向滑动查看长行。
3. **事件侧栏改成"自己维护"**：只列出资源上**已经声明**的时点（`item.events` 的键），
   不再把目录里十几个时点全摊开；每个时点右边有 × 可移除，「＋ 添加时点…」
   从剩余目录里挑一个并写入 `item.events[key] = { steps: [] }`。
   刚添加的空时点会被"钉住"（`this._pinnedEvent`），不会被"自动跳到有内容的时点"抢走。
