# 自定义窗口写卡指南（`request_ui`）

> 面向：想给卡牌加「弹出窗口让玩家选择 / 输入」的模组作者。
> 本文的口径全部对齐当前引擎（`Python联机版/mod_runtime_v2.py` 的
> `_sanitize_ui_component` / `validate_v2_ui_response`）与编辑器 v1.7.3。

## 一、30 秒上手

编辑器里新建一张卡，模板行点「输入数字窗口 / 口令记忆窗口 / 分页选择窗口」，
生成的卡**直接能玩**：窗口、步骤链、后续结算都写好了，改文案即可。

想自己写，最小的一步是这样：

```json
{"op": "request_ui", "component": "your_mod:my_window", "save_as": "pick",
 "target_player": "source", "timeout_ms": 60000, "on_invalid": "keep",
 "on_cancel": [{"op": "log", "message": "取消了"}]}
```

玩家提交的结果落在 `save_as` 指定的变量里，读法是：

```json
{"op": "get", "object": {"op": "var", "name": "pick"}, "key": "amount"}
```

## 二、窗口的两种写法

| 写法 | 长什么样 | 什么时候用 |
|---|---|---|
| **具名窗口**（推荐） | `registries.ui_components` 里定义一份，步骤里写 `"component": "your_mod:my_window"` | 多个事件/多张卡复用；编辑器有结构树、属性面板、预览 |
| **内联窗口** | `"component": {"type": "modal", "controls": [...]}` 直接写在步骤里 | 只用一次的小窗口 |

短名（`my_window`）在导出时会被补成 `<namespace>:my_window`，编辑器自动处理；
手写 JSON 时两个位置**要么都写短名、要么都写全名**，别一个短一个全。

## 三、控件清单

编辑器下拉里 22 个名字，其中 6 个是**别名**（运行时归一到已有控件，行为完全一样）：

| 你写的 | 运行时归一成 | 说明 |
|---|---|---|
| `radio_group` | `select` | 单选按钮组 |
| `zone_picker` | `select` | 选项是五个区域名 |
| `divider` / `warning_text` / `dynamic_text` / `preview_value` | `text` | 分隔线 / 警示 / 会求值的文本 |
| `input` | `text_input` 或 `number_input` | 看 `value_type`（`text` 默认 / `number`） |

真正要记的是这 15 个运行时控件：

| 控件 | 关键参数 | 玩家看到什么 |
|---|---|---|
| `text` | `text_cn`（`dynamic_text`/`preview_value` 还会求值 `value`） | 一行说明文字 |
| `text_input` | `max_length`（硬上限 200）/ `min_length` / `pattern` / `normalize` / `moderation` / `placeholder_cn` / `help_text` / `required` / `default` / `default_from` | 输入框 |
| `number` / `number_input` / `slider` | `min` / `max` / `step` / `default`（都能写取值表达式） | 数字输入 / 滑条 |
| `select` / `card_catalog_picker` | `options` / `default` / `default_from` | 下拉框 |
| `checkbox` | `default`（true/false） | 开关 |
| `multi_select` | `options` / `min_select` / `max_select` / `default` | 多选列表 |
| `card_picker` / `multi_card_picker` | `zone` / `target` / `allowed_instance_ids` | 选手牌 / 多选牌 |
| `equipment_picker` / `multi_equipment_picker` | 同上（区域默认装备栏） | 选装备 |
| `player_picker` / `target_picker` | `allowed_player_ids` | 选玩家 |

所有控件都支持：

* `label_cn` / `label_en`（缺中文只会警告，但界面上就没标题了）；
* `tab` + `tab_cn` 分页：同一个 `tab` 归为一页，**≥2 页**才画切换条，
  没写 `tab` 的控件留在切换条之上当"公共区"；
* `visible_if` / `disabled_if`：条件算子，或 `{"control": "<兄弟控件 id>", "equals": …}` 联动；
* `required`：必填（被联动隐藏的控件不参与必填）。

## 四、`request_ui` 自己的参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `component` | 必填 | 窗口 id 或内联对象 |
| `save_as` | `ui_result` | 结果存进哪个变量 |
| `target_player` | `"source"` | 窗口弹给谁（目标选择器） |
| `timeout_ms` | `0`（不限时） | 可以写取值表达式；超时按"取消"处理 |
| `on_invalid` | `"close"` | 玩家填了非法值怎么办：`close` 关窗按流程继续；`keep` **保持窗口让玩家改** |
| `on_cancel` | `[]` | 玩家点取消后执行的步骤列表 |

窗口对象本身：

```json
{"id": "your_mod:my_window", "type": "modal", "title_cn": "标题",
 "controls": [...],
 "buttons": [{"id": "confirm", "text_cn": "确定", "role": "confirm"},
             {"id": "cancel", "text_cn": "取消", "role": "cancel"}],
 "style": {"accent": "thorn", "panel": "solid", "size": "medium", "icon": "thorn"}}
```

按钮最多 **6 个**、每个必须有 `id`（没有 id 会被丢弃）；`role: "cancel"` 只是次按钮样式，
真正的取消语义看按钮 id / role 与 `on_cancel`。

## 五、三条容易记错的语义（都实测过）

**1. 输入记忆 `default_from` 的作用范围**

```json
"default_from": {"player_var": "last_note"}   // 玩家变量（同一局内保留，含换回合）
"default_from": {"card_var": "note"}          // 某张牌的 custom_vars
"default_from": {"var": "saved"}              // 本次事件上下文变量
```

* 同一局内**换回合不清**；玩家状态会序列化（`to_dict()` 带 `custom_vars`），
  所以重连回来记忆还在；
* **不跨局**：新的一局是全新的玩家状态，读不到就回落到控件自己的 `default`。
  想让玩家"下次登录还看到上次输入"，目前引擎没有这种持久化，需要另设机制；
* `player_var` 可以带 `"target": "enemy"` 之类的选择器换人读。

**2. 非法回应怎么处理**

服务端会硬校验：数字越界 / 必填为空 / 文本超长或不符合正则 / 触发违禁词 →
**拒绝这次回应**。这时：

* `on_invalid: "close"`（默认，老卡行为）：关掉窗口、记一条模组错误、按流程继续；
* `on_invalid: "keep"`：窗口留着（会重新推给玩家并重排超时），玩家能改。

**3. 违禁词过滤 `moderation`**

| 值 | 行为 |
|---|---|
| `mask`（默认） | 风险等级 ≥3 打码后放行；≥4 直接拒 |
| `reject` | 等级 ≥3 就拒（口令类输入用这个） |
| `off` | 不过滤（例如纯口令比对卡） |

文本还会先按 `normalize` 归一：`trim`（默认，去首尾空白）/ `lower` / `trim_lower` / `none`。

## 六、常见坑

1. **`select` / `card_catalog_picker` 的默认值**依赖客户端（批次 CR 修过）——
   旧版本客户端会把默认值忽略、停在第一项；写记忆类窗口时注意玩家客户端版本。
2. 控件 `id` 必须唯一且非空；重复 id 编辑器会报错。
3. 按钮缺 `id` / 超过 6 个：引擎**静默丢弃**，发布期与编辑器只给 warning。
4. 数值控件的 `min`/`max` 可以写表达式（例如上限取玩家体力）——
   但玩家提交时会按**当时算出来的**范围校验，别写出"提交后才变范围"的窗口。
5. 分页只是布局：控件数据仍然是一层平铺的 `controls`，读值方式不变。

## 七、怎么验

| 手段 | 命令 / 位置 | 能发现什么 |

| 编辑器本地校验 | 编辑器里随便改一下就会跑，导出前必跑 | 控件类型、词表、按钮、必填文案 |
